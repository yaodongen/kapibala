# Kapibala 命令行（kapi）

[English](./cli.md) · **简体中文**

`kapi` 是桌面版的命令行孪生体：共用同一个 core package、同一份库、同一份库列表，两边可以同时开着（§6）。本文讲怎么用；它为什么存在（M3 闸门、为什么为了它排除 Tauri）见 [`architecture.zh.md` §9](./architecture.zh.md#9-实施顺序)，锁和库列表的磁盘细节见 [`storage.zh.md`](./storage.zh.md) §2.1、§4.3。

---

## 1. 装上

```bash
make deploy      # 装依赖 → 环境自检 → 类型检查 + 测试 → 把 kapi 写进 ~/.local/bin
kapi --help
```

`kapi` 是个指回仓库源码的 wrapper（`~/.local/bin/kapi`），改代码立刻生效，没有编译步骤。不装也能跑：

```bash
make run ARGS="add 买菜 --at today"      # 等价于 node apps/cli/src/index.ts …
node apps/cli/src/index.ts today
```

要求 Node 22.18+（直接跑 `.ts`）。wrapper 里写死了当时那个 `node` 的绝对路径：换 node 版本要重跑 `make deploy`，或临时用 `KAPI_NODE=/path/to/node kapi …`。卸载用 `make unlink`（只删那个 wrapper）。

环境变量（正常使用不需要，都是给测试和 spike 用的）：

| 变量 | 作用 |
| --- | --- |
| `KAPIBALA_USER_DATA` | 覆盖本机状态目录（库列表、锁、日志）。在一台机器上模拟两台 Mac 就靠它 |
| `KAPIBALA_MACHINE_ID` | 覆盖机器指纹。库被整体复制过、或整机迁移，就是靠它认出来的 |
| `KAPIBALA_LABEL` | 设备显示名，默认主机名；`doctor` 里显示的就是它 |
| `NO_COLOR` | 关掉颜色输出 |

## 2. 库（vault）

| 命令 | 作用 |
| --- | --- |
| `kapi vault create <目录>` | 在**空目录**里新建一个库，并设为当前库 |
| `kapi vault open <目录>` | 打开已有的库，并设为当前库 |
| `kapi vault list` | 列出所有库，`●` 是当前库 |
| `kapi vault use <名字\|路径\|id尾号>` | 切换当前库 |
| `kapi vault forget <名字\|路径\|id尾号>` | 从列表里移出（**不删目录**） |

库列表存在本机状态目录里 —— macOS 是 `~/Library/Application Support/Kapibala/vaults.json`，Windows 是 `%APPDATA%\Kapibala\vaults.json`。**它不在库目录里**：库目录会被同步到别的机器上，库列表跟过去毫无意义（[`storage.zh.md` §2.1](./storage.zh.md#21-库注册表vaultsjson)）。桌面版和 CLI 读的是同一个文件，所以在哪边建的库，另一边都看得见。`forget` 只是移出列表，想真删自己删目录。

任务类命令（§3）都作用于**当前库**，没有 `--vault` 这种一次性指定。打开库时有两种情况会提示：

- 这个设备目录不属于本机（库被复制过、或整机迁移）→ 换用新的设备身份继续跑，并提示一句（[`storage.zh.md` §4.2](./storage.zh.md#42-库目录被整体复制必须处理的坑)）。
- 库格式比当前 CLI 新 → 只读打开，任何写操作直接报错。

## 3. 任务

| 命令 | 作用 |
| --- | --- |
| `kapi add <标题> [--at 时间] [--repeat …] [--after]` | 新建任务；标题是剩下的所有参数，空格拼起来 |
| `kapi today` | 今天 + 逾期（未完成的） |
| `kapi ls [--all]` | 最近 7 天；`--all` 是全部未完成的 |
| `kapi done <id>` | 完成（周期任务顺带生成下一期，并把下一期的 id 打出来） |
| `kapi undone <id>` | 取消完成 |
| `kapi rm <id>` | 移入垃圾桶 |
| `kapi trash` | 看垃圾桶 |
| `kapi restore <id>` | 从垃圾桶恢复 |
| `kapi purge <id>` / `kapi purge --all` | 彻底删除 / 清空垃圾桶 |
| `kapi search <关键词>` | 搜标题和备注 |
| `kapi doctor` | 库和同步状态 |

几条约定：

- **id 给尾部几位就行。** 列表里显示的是 ULID 最后 6 位，命令接受任意长度的尾部；撞了会告诉你匹配到几个，多给几位。显示的那 6 位可以直接粘回去。`vault use` / `vault forget` 认的是库 id 的尾部（大写）。
- **`today` / `ls` 只列没完成的。** 已完成的不在这里 —— 目前没有正式的"看已完成"命令，调试用的 `done-list` 没进 `--help`。
- **`ls` 是"最近 7 天"，而且含更早的逾期。** 逾期的一组永远置顶（红色），然后按日期升序，最后是"未安排"。
- **没带 `--at` 建出来的是"未安排"**，只在 `ls --all` 里出现。
- **删除是两级的**：`rm` 进垃圾桶（`restore` 能捞回来），`purge` 之后列表里就再也不出现 —— 但存储层永不物理删除，日志里仍留着痕迹（[`storage.zh.md` §5.1](./storage.zh.md#51-op-格式)）。
- **`search` 按空格分词，全部命中才算**（AND），标题和备注都搜，不猜你想搜什么；标题命中的排在备注命中的前面。
- **`doctor`** 打库路径、设备身份（共几台设备）、任务数，以及日志健康：坏行数、丢弃的未写完尾行、有文件读不出来（iCloud 占位符还没下载下来时会报这个）。

## 4. `--at` 认得的写法

| 写法 | 例子 | 落在 |
| --- | --- | --- |
| 今天 / 明天 | `today`、`今天`、`tomorrow`、`明天` | 那一天 00:00（全天） |
| 相对天数 / 周数 | `+3d`、`+2w` | 今天往后 N 天 / N 周（全天） |
| 星期 | `fri`、`周五`、`FRI` | **最近的那一次**（全天）；今天就是那天时算下一周 |
| 日期 | `2026-08-28` | 那天 00:00（全天） |
| 日期 + 时间 | `2026-08-28T19:30`、`2026-08-28 19:30` | 那个时刻 |
| 只给时间 | `19:30`、`7:30` | 今天那个时刻 |

几点注意：

- 月份和日子要**两位**：`2026-08-28` 行，`2026-8-28` 会报"看不懂的时间"。
- 只有这几种。界面里那套自然语言（`下周三`、`3天后`、`每周五`）不在 `--at` 里，写了直接报错 —— 要那种就去界面上说。
- 星期口径和界面完全一致（core 的 `when.ts`）：**取最近的那一次**，今天就是那天时算下一周。所以周三说 `fri` 指的是**这**周五。
- 时间给的是本地时区。

## 5. `--repeat`

只有 `daily` / `weekly` / `monthly` 三个词，加 `--after` 切换模式：

| | 默认（fixed） | `--after`（afterCompletion） |
| --- | --- | --- |
| 下一期从哪算 | **这一期自己的日期** + 一个周期 | **完成时刻** + 一个周期 |
| 拖到晚了才勾 | 不漂，还是原来的节奏 | 顺延 |

下一期的 id 是从"这一期"派生的（系列 + 上一期），所以两台 Mac 各自勾了同一次，会算出同一个 id，同步后合并成一条，不会变成两条。`UNTIL` 到了、或者系列结束，`done` 就不再生成下一期（[`storage.zh.md`](./storage.zh.md) 之外，派生规则在 `packages/core/src/repeat.ts` 顶部有完整说明）。

CLI 只开了这三个预设。间隔大于 1（"每两周"）、工作日、每月第几个周几这些 core 的 rrule 能力，得去界面上设 —— 设完 CLI 照常读得到。

## 6. 和桌面版同时用

可以同时开着，共用同一份日志。同一台机器上两个进程都想写同一个设备目录，靠一把**本地**锁串起来（锁文件在状态目录下，不在库目录里 —— 库目录里的锁会跟着 iCloud 同步到别的机器，毫无意义）：

- 拿不到锁会最多重试 2 秒，然后报「另一个 Kapibala 进程正在写这个库，稍后再试」，退出码 1。
- 持锁进程已经死了（崩溃留下的锁文件）会被认出来清掉，不会永久卡住。
- **跨机器不需要锁**：每台机器只写 `devices/<自己的 id>/`（[`storage.zh.md` §4.3](./storage.zh.md#43-同一台机器上的多进程)）。

CLI 每次启动都重新扫盘，所以别的机器刚同步过来的改动，下一条命令就能看到。

## 7. 输出和退出码

- 出错时信息走 stderr、退出码 1（找不到任务、看不懂的时间、库不可写、拿不到锁……）。
- **未知命令同样是 1**（`kapi nope`、`kapi vault nope`）：帮助照打，省得你不知道下一步，但退出码不为 0 —— 脚本里 `kapi typo && …` 不会被当成成功。只有"命令是对的、只是要看帮助"才是 0：`--help`、`help`、什么都不给、光说 `kapi vault`。
- 颜色只在 tty 上开；管道、重定向、`NO_COLOR` 下是纯文本，可以直接喂给别的命令。
- 列表顺序：已逾期（置顶）→ 按日期升序 → 未安排。

## 8. 还没有的命令

- **改任务**：只能新建和勾选，改标题 / 备注 / 改期要用桌面版（改的是同一份日志，CLI 下一条命令就能看到）。
- **看已完成**：没有正式命令，只有没进 `--help` 的 `done-list`。
- **界面那套自然语言解析**（`--at` 只认 §4 那几种）。
- **完整的重复规则**（§5 末尾）。
- **统计 / 导出**：没有。
